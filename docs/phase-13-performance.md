# Phase 13 Performance Baseline

## Purpose

This document records the reproducible method and the measured development-host
baseline generated by `scripts/run_phase13_benchmark.py`. It is not an SLA,
production capacity claim, public benchmark, or detection-performance result.

## Workload and method

- Input: reviewed `phase12-presentation-demo.pcap`
- Input SHA-256:
  `0d272ac98660eb119cded8be194a513c2db82b475d4cce982a120eb210a8ab51`
- Per iteration: 32 captured packets, 9 finalized flows
- Feature schema: `1.0.0`
- Warm-ups: 2
- Measured repetitions: 10
- Execution: one offline process, sequential operations, no root, no live
  capture, no network target
- Latency percentiles: deterministic linear interpolation over iteration
  durations
- CPU: process CPU time
- Peak memory: process RSS sampled every 2 ms
- Random seed: `4204`
- Artifacts: generated below an ignored, isolated Phase 13 temporary namespace;
  no active pointer or formal evidence root is changed
- Full pipeline: a fresh temporary SQLite database per iteration

Machine-readable environment, dependency, model/policy identity, checksum, and
artifact-size evidence is stored in:

- `reports/hardening/phase-13/performance/benchmark-results.json`
- `reports/hardening/phase-13/performance/benchmark-results.csv`
- `reports/hardening/phase-13/performance/performance-baseline.md`

## Measured result

| Component | Unit | Throughput/s | p50 ms | p95 ms | p99 ms |
| --- | --- | ---: | ---: | ---: | ---: |
| PCAP packet parsing | captured packets | 207769.5420 | 0.1412 | 0.2012 | 0.2175 |
| Flow aggregation and feature extraction | captured packets | 13380.1863 | 2.1116 | 3.6654 | 3.8370 |
| Supervised inference | flow rows | 8055.6427 | 1.0537 | 1.4234 | 1.4999 |
| Anomaly inference | flow rows | 11703.8276 | 0.7703 | 0.8379 | 0.8391 |
| Fusion | score pairs | 229617.0243 | 0.0377 | 0.0462 | 0.0510 |
| Full flow-to-alert pipeline | persisted flows | 1.4590 | 6138.5708 | 6298.0385 | 6339.9716 |

The raw result also records CPU and peak RSS per component. The largest bundle
in this run was the isolated supervised bundle at 1,615,885 bytes; the anomaly
bundle was 42,166 bytes, the explanation artifact 36,003 bytes, and the fusion
policy 3,618 bytes.

## Interpretation and limitations

- Full-pipeline latency includes validated isolated artifact reuse, SQLite
  initialization, ingestion/replay, detection, alert persistence, correlation,
  and hypothesis processing; it is not equivalent to model inference latency.
- The sample is deliberately small and synthetic.
- Host scheduling and thermal state affect timings.
- RSS sampling can miss sub-2 ms peaks and records process-wide memory.
- No hard latency threshold is used in CI. CI should run only `--smoke`.
- No bottleneck-driven optimization claim is made from this single-host run.
  The deadline heap was a prior security-complexity remediation, not a
  benchmark-tuned model or policy change.

## Reproduction

```bash
PYTHONPATH=src .venv/bin/python -m scripts.run_phase13_benchmark \
  --warmups 2 \
  --repetitions 10
```

For a deterministic execution check without a latency gate:

```bash
PYTHONPATH=src .venv/bin/python -m scripts.run_phase13_benchmark \
  --smoke \
  --output-dir /tmp/aegishunt-phase13-benchmark-smoke
```
